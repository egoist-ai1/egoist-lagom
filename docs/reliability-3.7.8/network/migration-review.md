# Перенос конфигураций установленных оболочек

Проверено чтением текущих исходников кандидата 3.7.8; установка и изменение живых служб не выполнялись. Код переноса принадлежит общей процедуре установки и не менялся в рамках сетевого подзадачи.

В `scripts/invoke-final-silent-reinstall.ps1` защищённая переустановка сохраняет `Runtime` и регистрации служб, останавливает принадлежащие продукту службы, запускает кандидат, затем вызывает `Restore-PreservedState`, `Update-PreservedRuntimeReliability` и `Start-PreservedServices`. Поэтому на этом пути старые XML исправляются **до** возобновления служб и независимо от открытия приложения.

`Update-PreservedRuntimeReliability` рассматривает только зарегистрированные собственные SystemDoH, TelegramProxy и Zapret. Он требует остановленного состояния, совпадения пути регистрации с ожидаемой оболочкой и идентификатора XML. Ограничивает размер XML, запрещает DTD, внешнее разрешение XML и reparse points. Записывает `sizeThreshold=10240`, `keepFiles=5`, задержки 5/10/60 секунд и `resetfailure=1 hour` через атомарную замену файла. Исполняемый файл, аргументы, рабочая папка, выбранный профиль и параметры Telegram этим преобразованием не заменяются. После миграции запускаются ранее работавшие службы; Core запускается отдельно. Ошибка возвращается в процедуру восстановления резервного состояния.

В обычном запуске Core надзор за службами ремонтирует политику восстановления SCM, но не обновляет XML WinSW. Генератор Telegram обновляет XML при установке/запуске/изменении настроек. `ZapretManager.ensureProvisioned()` исправляет XML только для отдельных старых сигнатур некорректной конфигурации (`AppData\\Roaming` и `quic_initial_dbankcloud_ru.bin`); старый лимит журналов сам по себе не вызывает этот ремонт. Поэтому замена файлов приложения и последующая перезагрузка без защищённого переноса не доказывают обновление старых XML.

Есть различие двух путей установки. В `src/installer/setup.nsi` обычная интерактивная установка переходит к защищённой переустановке при коде проверки безопасности 54. Текущий `owned-cleanup.ps1` теперь требует этот путь для **любой идентифицированной существующей установки**, если проверенное защищённое окно переноса ещё не создано; активный SystemDoH больше не является единственным условием. Прямой путь `PostInstall` вызывает `Remove-OptionalOwnedServices` и `Discard-OwnedNetworkArtifacts`, оставляя компоненты выключенными и требуя нового подключения: это чистая установка, а не перенос работающих служб.

Первоначальная рекомендация направлять любой проверенный upgrade в защищённый перенос реализована основным исполнителем и подтверждена повторным чтением исходников. Новая чистая установка остаётся на прямом пути. Для приёмки после перезагрузки нужен отдельный отчёт основного исполнителя: сохранение настроек, новые XML, режимы запуска и работоспособность без интерфейса не считаются доказанными одним чтением исходников. Проверка TCP Telegram при переносе также требует собственного владельца слушателя, чтобы порт Relay не мог подтвердить чужую готовность.
