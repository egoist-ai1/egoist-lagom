# Проверка жизненного цикла сети — 3.7.8

Исправлены воспроизведённые ошибки в управлении Telegram Proxy, Zapret, VPN, переключении компонентов и завершении приложения. Последняя проверка текущего рабочего кандидата: **158 тестов пройдены, 0 ошибок, 0 пропусков**, Node.js 24.19.0, Windows; 11,660 секунды. Это проверки исходников и управляемых имитаций, а не испытание установленной службы в течение месяцев.

## Что изменилось

| Область | Подтверждённая проблема | Исправленное поведение |
| --- | --- | --- |
| Telegram | Служба SCM могла быть Running при недоступном локальном порте или чужом слушателе Egoist Relay. | `serviceRunning` сохраняет состояние SCM; `listenerReady` и `runtimeReady` требуют доступного слушателя в собственном дереве процессов. `listenerOwnership` различает собственный, чужой, отсутствующий и неизвестный слушатель. Перед изменением/запуском службы чужой и неизвестный владелец блокируют действие. Проверка ограничена 4 секундами; команда не читает аргументы процессов и секреты. |
| Telegram | При тайм-ауте остановки код продолжал очистку процессов; ремонт автозапуска перерегистрировал службу. | Неуспешная остановка возвращает ошибку и сохраняет процессы. Ремонт выполняется без удаления регистрации. Явное выключение отключает автозапуск; временный перезапуск настроек сохраняет его. Закрытие интерфейса сохраняет установленную фоновую службу. |
| Telegram и Zapret | Запрос статуса, начавшийся до операции, мог перезаписать новый кэш старым состоянием. | Поколение кэша меняется при операции; устаревший запрос не публикует результат в новый кэш. Параллельные запросы одного поколения используют общий запрос. |
| Запуск служб | START_PENDING мог восприниматься как остановленная служба, после чего очистка убивала запускающийся процесс. | Код ждёт подтверждённого перехода SCM. STOP_PENDING также проверяется до повторного запуска и передачи управления VPN. Неизвестное состояние не считается безопасным остановленным состоянием. |
| Zapret | Running у оболочки службы считалось готовностью без работающего собственного `winws`. Смена профиля удаляла регистрацию службы. | Добавлена проверка собственного процесса; выбор одинаковой конфигурации не перезапускает службу. Новый профиль публикуется с сохранением регистрации. При ошибке восстанавливаются предыдущие XML, профиль и прежнее рабочее состояние; ошибка отката сообщается отдельно. |
| Zapret standalone | Остановленная автоматическая регистрация службы могла запуститься после перезагрузки поверх явно выбранного отдельного процесса. | Явный start/restart standalone требует подтверждённой остановки SCM и отключает её автозапуск до запуска процесса. Временная приостановка службы для VPN сохраняет прежний автоматический режим. |
| VPN | `ChildProcess.killed` принимался за подтверждение завершения. При ошибке очистки терялась ссылка на сеанс. | Проверяется реальное завершение процесса. После ограниченного ожидания применяется сигнал через исходный `ChildProcess`, затем проверяется результат. Пока процесс жив или восстановление настроек не завершилось, сеанс сохраняется для повторной очистки. Очистка уходящих сеансов проходит через очередь операций. |
| VPN | Длительное отсутствие сети исчерпывало попытки и оставляло VPN выключенным до ручного вмешательства. | Сетевые ошибки и остановка процесса используют ограниченные серии попыток, затем паузу по умолчанию 5 минут. Отмена удаляет таймер. Ошибки авторизации и конфигурации требуют исправления пользователем. |
| Переключение и завершение | Зависшая проверка владельцев ресурсов обходила срок операции. После тайм-аута завершения могли запускаться следующие изменения сети. | Проверка ограничена оставшимся сроком; операция не запускается после тайм-аута. Координатор завершения не начинает следующие шаги после истечения срока, возвращает стабильный снимок отчёта. |
| Shield | Статус оболочки скрывал неготовность компонента; старая ошибка оставалась после подтверждённого восстановления. | Явные `runtimeReady=false`/`listenerReady=false` исключают успешное подключение. Текущая ошибка снимается только после свежего подтверждения требуемого состояния. `lastActionError` сохраняет историю неуспешного действия. |
| Журналы оболочек | `sizeThreshold=10485760` означает 10 ГиБ при единицах WinSW в КБ. | Генерируемые XML используют `10240` КБ, 5 архивов, перезапуск через 5/10/60 секунд и сброс счётчика через час. Это предел одного потока журналов оболочки, а не общий предел всех файлов продукта. |

Основные изменения находятся в `src/recovered/electron/ipc/{telegram-proxy-manager,zapret-manager,vpn-manager,vpn-reconnect-supervisor,network-combinator-manager}.js`, `src/recovered/electron/shutdown-coordinator.js` и `src/shield-connection-controller.js`. Добавлены 30 поведенческих сценариев в `tests/network-lifecycle-reliability.test.mjs` и 16 в `tests/telegram-listener-ownership.test.mjs`. В `tests/service-status-locale.test.mjs` проверка отсутствующей службы сравнивает значение состояния, а не идентичность объекта: код SC 1060 теперь является прямым подтверждением отсутствия службы. Исправлена также присваивающая системную переменную `$PID` ветка CIM; её фактическое выполнение в PowerShell проверено отдельным сценарием.

Начальные сценарии создавались последовательно: эти запуски не являются одним полным прогоном всего проекта до исправлений.

- В первоначальных 12 сценариях прошёл 1, не прошли 11; отдельно воспроизведены 3 ошибки смены профиля и 2 ошибки START_PENDING.
- Перед исправлением проверки владельца порта и автозапуска standalone отдельно воспроизведены 7 отказов из 7 сценариев.

- За 90 **моделируемых** дней отсутствия сети выполнено 143009 неуспешных попыток переподключения; одновременно в планировщике находился не более одного таймера. Серии ограничены 8 попытками, ручная отмена удаляет запланированную попытку.
- Синтаксис 7 изменённых исходников и 2 новых тестов проверен `node --check`; `git diff --check` для затронутых файлов прошёл.

## Практические пределы

Открытый локальный порт Telegram не доказывает прохождение удалённого трафика; принадлежность слушателя теперь проверяется отдельно. Работающий собственный процесс Zapret не доказывает доступность любого сайта или медиапотока. Эти статусы нельзя представлять как универсальную проверку интернета.

Автовосстановление VPN в этой реализации требует работающего процесса приложения. Дежурство Windows Core и восстановление установленных служб проверяются отдельно в отчётах Core. Случайное завершение приложения, перезагрузки Windows, обновления драйверов, переполнение диска, реальные сетевые обрывы и длительная работа установленного пакета не проверены этим набором имитаций. Автоматизированные проверки не изменяли живые службы, сеть, реестр и установленное приложение. Реальное обнаружение конфликта и отдельная проверка сосуществования описаны в [telegram-coexistence.md](telegram-coexistence.md).

Путь переноса старых XML после обновления разобран в [migration-review.md](migration-review.md). Полная гарантия беспрерывной работы месяцами из этих результатов не следует; подтверждены конкретные исправления и перечисленные инварианты.

Контракты: [единицы журналов WinSW 2.12.0](https://github.com/winsw/winsw/blob/v2.12.0/doc/loggingAndErrorReporting.md), [семантика ChildProcess.killed](https://nodejs.org/api/child_process.html#subprocesskilled).
