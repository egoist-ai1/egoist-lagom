# Интерфейс Lagom 3.7.8: изменения и проверка

Проверка выполнена 29 сентября 2026 года в Chromium 153.0.8010.12. Исходная база — Lagom 3.7.7, commit `b8662d3`; проверяемый интерфейс собран из изменённых исходников 3.7.8. Сохранена компактная монохромная тема.

## Что исправлено

- У виджета появился синхронный общий блокировщик действий. Повторные нажатия до первого ответа службы не отправляют несколько подключений; переключение DNS и Telegram не пересекается с подключением и друг с другом.
- До первого ответа `shield.status` показывается «Проверяем состояние…», сетевые действия недоступны. Ошибку чтения состояния можно перепроверить. Старый ответ или отказ опроса не заменяет более свежий статус события; опрос не снимает блокировку незавершённого действия.
- DNS и Telegram сверяют результат переключения со свежим состоянием службы. Ответ `ok:true` при противоречащем ему состоянии не переводит переключатель в желаемое положение и не сохраняет ложное предпочтение.
- `runtimeReady:false`, `listenerReady:false` и `verified:false` учитываются явно. Запущенная оболочка службы не означает готовность рабочего процесса, слушателя Telegram или DNS. В обзоре неготовая служба показана выключенной с подписью «Служба не готова». При остановке Telegram дополнительно требуется отсутствие работающей фоновой службы.
- Текущее исправное подключение отделено от ошибки последнего пользовательского действия. Ошибка сохраняет подробности, но сама по себе не превращает подтверждённое работающее подключение в отключённое.
- Успешное событие проверки обновления доходит через preload вместе с данными, снимает устаревшую ошибку и восстанавливает доступность проверки. Ошибка транспорта отличается от отказа проверки доверия. Отказ начального IPC больше не оставляет кнопку в вечном состоянии «Проверяем…». Старый ответ начальной проверки не заменяет более свежее событие; отклонённый повторный запрос не отменяет результат принятого запроса.
- Уменьшенная анимация применяется к Framer Motion, CSS и GSAP. В подключённом виджете нет постоянной анимации контура; движение при выполнении операции сохраняется и при скрытии окна приостанавливается. Удалены повторные вызовы изменения нативного режима окна.
- Кнопки виджета имеют размер не менее 24 × 24 CSS px. Длинная ошибка прокручивается, получает фокус клавиатуры и сохраняет весь текст. При размере 148 × 170 CSS px, соответствующем половине штатного размера при масштабе 200%, содержимое прокручивается; нижние кнопки не перекрывают подробности ошибки.
- В окне «О приложении» используется имя Egoist Lagom. Убраны непроверенные оценки DNS «Быстро», «Безопасно», «Совместимо»; подсказка переподключения описывает попытку восстановления, а не гарантирует результат.

| Повторная проверка обновления после ошибки IPC | 100 нажатий отправили 1 действие; успешный результат сохранился |

| Статический детектор impeccable для изменённых brand-компонентов и CSS | Нет найденных замечаний; это не сертификат доступности |

Браузерные проверки охватывают сохранение настроек, зависимость автозапуска от автоподключения, возврат фокуса и замыкание Tab в диалогах, подсказки на узком окне, перенесённый текст кнопок, сохранение черновика Telegram, неготовые службы, ошибки и восстановление обновления, уменьшенную анимацию, размеры 1440/820/550 и эквиваленты увеличенного масштаба 550 × 370 и 512 × 364.

`baseline-widget-race.json` хранит воспроизведённый отказ исходного интерфейса. `compact-ui-report.json` содержит перечень проверок, вызовы тестового API и SHA-256 файлов проверенной сборки. `widget-report.json` содержит результаты виджета. Проверки запускаются скриптами `scripts/check-compact-ui.mjs` и `scripts/check-shield-widget.mjs`; `EGOIST_UI_BUILD_DIR` позволяет указать абсолютный каталог отдельной сборки. Node-проверки находятся в `tests/ui-service-readiness.test.mjs`.

## Область доказательства

Браузерные сценарии используют управляемые ответы API в отдельном headless-браузере. Они подтверждают поведение интерфейса и количество отправленных запросов. Два запроса старого интерфейса не доказывают два запуска реальной службы: backend мог объединять их.

Эта проверка не меняла установленное приложение, службы Windows, DNS, маршруты или пользовательские настройки. Она не подтверждает реальную работу сети после перезагрузки и не заменяет проверки backend/установщика. Нативный DWM, реальные права Windows, производительность CPU/энергопотребление и месяцы непрерывной работы здесь не измерялись.

Снимки рядом с отчётом показывают тестовые состояния: обычный виджет, полные подробности ошибки, ошибку при масштабе 200%, Telegram без готового слушателя, восстановление проверки обновления и узкий диалог. Данные на них — фикстуры, а не результаты установленного приложения пользователя.
