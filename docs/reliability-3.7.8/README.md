# Egoist Lagom 3.7.8 — аудит и проверенные изменения

Проверена установленная Windows-версия **3.7.7**, актуальный GitHub `egoist-ai1/egoist-lagom` и локальные Windows-копии Shield. База исправлений — `b8662d31128f6366a86c9f2be6d9bbaab60d387c`. Результат — один Windows-проект Lagom и сборка **3.7.8**. Историческая приватная разработка Shield 3.6 переведена в архив, её история сохранена в проверенном локальном Git bundle.

Исправления подтверждают конкретные сценарии отказов, а не безошибочную работу при любых условиях. Месяцы реального uptime, перезагрузки компьютера, смена драйверов и всех возможных сетей не были проверены. Точные итоговые результаты сборки, установки и очистки сохраняются в `verification/` и отдельном итоговом receipt.

## Что фактически установлено

Окончательная сборка **3.7.8 установлена 29 сентября 2026 года**. SHA256 установщика: `34136729F0924E95AF65B7FEFD2792763C29694056B8FF76A79C9FE0E325F927`. Шесть ключевых installed payload файлов, включая app.asar, worker, Core, trust root и оба installation scripts, совпали с проверенным пакетом. В извлечённом Core bundle подтверждён runtime **10.0.12**. Installation identity сохранён.

Живой readback 12:58 UTC подтвердил Core, SystemDoH, Zapret и Telegram Proxy в состоянии Running/Auto при **нуле процессов интерфейса**. Работает один собственный winws. `health.egoist.invalid` и внешний A-запрос `example.com` отвечают через `127.0.0.1` и `::1`. Все **12** строк DNS адаптеров совпали с состоянием до обновления; чужие настройки не сбрасывались.

При проверке выявлен настоящий конфликт Telegram: Relay занял `127.0.0.1:1443`, Lagom получил bind error 10048, а SCM остался Running. Порт 1444 тоже занят. Lagom переведён на свободный **1445**, с защищённым backup и изменением только port в собственных config/XML; Relay на 1443 сохранён. Итоговый installer подтвердил свой listener и реальное TCP подключение после восстановления. Ссылки, QR и web link в Lagom теперь используют сохранённый 1445. **Клиент Telegram со старой ссылкой 1443 требует однократного обновления подключения**; его настройка хранится отдельно и здесь автоматически не менялась. Удалённая доставка Telegram не проверена.

Последний installer выполнялся 39,4 секунды; от остановки DNS до итогового readback прошло 53,3 секунды. Точная длительность недоступности DNS внутри этого окна не измерялась. Это защищённое обновление с восстановлением, без заявления zero-downtime. [Installation/readback evidence](verification/receipt.json), [Telegram конфликт](network/telegram-coexistence.md).

## Службы без открытого приложения

Core запускается как автоматическая служба Windows. Внутри Core теперь работает самостоятельный цикл наблюдения за собственными установленными службами SystemDoH, Telegram Proxy и Zapret. Запуск интерфейса не требуется. При старте даётся 60 секунд на загрузку Windows; плановая проверка выполняется с интервалом 15 секунд, когда общая очередь привилегированных операций свободна. Длительная установка или транзакция может отложить эту проверку.

Core сохраняет намерение включить или выключить компонент в защищённом состоянии **до** команды управления. Явное выключение и Disabled не отменяются watchdog. Старая уже работающая собственная автоматическая служба включается в наблюдение; по остановленной legacy службе намерение не угадывается. Чужой service executable, неизвестное состояние SCM, чужой DNS или замена адаптера не дают права перезаписать конфигурацию.

При падении процесса используются SCM recovery actions и независимый контроль Core. Для работающего, но зависшего DNS проверяется локальный DNS-ответ; для Telegram — настроенный слушатель, принадлежащий SCM-процессу Lagom или его проверенным потомкам. CreationDate защищает от переиспользованного parent PID. Чужой или неизвестный владелец даёт конфликт, без попытки перезапускать службу в занятый порт. Три последовательных локальных отказа могут разрешить восстановление, с интервалом не менее пяти минут. Ошибки и повторные сообщения ограничены. Неудача внешнего DoH оператора сама по себе не вызывает бесконечных локальных перезапусков.

Это относится к установленным автоматическим службам. VPN и его повторное подключение в текущей архитектуре требуют работающего приложения. Локальный порт Telegram подтверждает слушатель, но не доставку удалённого трафика; собственный процесс Zapret также не доказывает доступность любого сайта.

## Ключ обновлений и переход

Два имевшихся локальных закрытых ключа не соответствовали реестру доверия 3.7.7. Дополнительный поиск в старом Shield не нашёл подходящего ключа. Пользователь поручил выбрать рабочий вариант без самостоятельного управления ключами. Созданы новые Ed25519 root/release keys; private files остаются только в `.local/release-secrets/recovery-2026-09-29`, исключены из Git и ограничены ACL текущего пользователя и SYSTEM. Private content в отчёты не выводился.

Новый root **не** подписан утраченным старым root. Это явная смена доверия через локальный проверенный установщик и Windows UAC, а не совместимое автоматическое продолжение старой цепочки. Старые версии не могут автоматически принять новую подпись. Минимальная версия нового контура автообновлений — 3.7.8. После ручного перехода 3.7.8 проверяет следующие релизы новым root; старые открытые release keys сохранены в registry для проверки исторических подписей. Проверка подписи не отключена, функция bootstrap по-прежнему отклоняет чужой private root.

Отпечатки и граница перехода: [trust-migration.json](trust-migration.json). Ed25519 release signature не является сертификатом Windows Authenticode: без отдельного Authenticode certificate Windows может показывать обычное предупреждение об издателе. Новый ключ не обещает отсутствие предупреждений SmartScreen.

## Существенные оставшиеся ограничения

- Локальный Xray DNS 26.5.3 отвечает на A/AAAA и отклоняет TXT/MX/SRV/HTTPS. Plaintext forwarding этих типов не включён. Новый стандартный DoH на поддерживаемой Windows использует native backend, но сохранённый legacy local режим не переносится незаметно без безопасной отдельной процедуры.
- При успешной ротации local hostname pins нужен короткий restart; полноценного zero-downtime hot reload нет. Переключение работающего local upstream/custom port может быть отклонено с сохранением текущей службы.
- Native refresh откладывается при физически отсутствующем сохранённом адаптере или внешнем изменении семейства; disconnected, но присутствующий GUID проверяется. Чужие DNS не перезаписываются ради формального success.
- Обслуживание раз в час/15 минут и recovery cooldown — ограничения нагрузки и конфликта, а не обещание мгновенного восстановления при любом отказе.
- Полная потеря сети, недоступный оператор, неверный сертификат, отказ диска/SCM/драйвера, выключенный компьютер остаются реальными причинами недоступности. Журналы и честный degraded/unknown статус позволяют их диагностировать.
- Реальный reboot/boot smoke и месяцы soak должны выполняться на отдельной Windows VM и в длительной эксплуатации. Аудит не перезагружал рабочий компьютер пользователя.

Пакет установлен локально и подготовлен для проверки изменений в GitHub. Стабильный публичный канал не переключался. Он не назван гарантированно безошибочным: измерены и устранены перечисленные конкретные отказы, а оставшиеся границы описаны явно.
