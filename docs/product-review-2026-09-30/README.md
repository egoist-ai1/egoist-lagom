# Повторный аудит Egoist Lagom и план доведения

Дата: 30 сентября 2026 года. Проверяемая база: кандидат **3.8.0**, commit **199236e3b227f9885c2beef64faffbe9e9a35583**. Установленная и опубликованная версия — **3.7.9**.

**Кандидат пока не готов к продвижению в stable.** Повторный аудит обнаружил воспроизводимые дефекты, которые не покрывает успешный базовый набор тестов. Этот пакет содержит исследование, доказательства, приоритеты, план реализации и отдельный макет дизайна. В исходниках исправлены установка поверх самовосстанавливающихся служб, сохранение startup policy, восстановление при загрузке Windows, зависший worker, конфликт удаления и запись установочного журнала. Большинство остальных задач аудита остаются открытыми. Новая установка и публикация ещё не выполнены.

Подробности новой реализации и её границы: [installer-fix.md](installer-fix.md). После последней правки общий набор **644/644 PASS**, 0 fail/skip/cancel; helper **43/43**, lifecycle **9 групп**, boot recovery **22 группы / 490 assertions**, timeout recovery **8 групп**, новый Core self-test **exit 0**. Настоящие SCM restart queue, upgrade/reboot/power-loss и длительный soak остаются обязательной приёмкой.

Вывод о готовности из прежнего receipt нельзя использовать без этих новых результатов. Старые receipts сохранены как история проверок своего снимка; их файлы и provenance не переписаны.

## Что мешает выпуску

| Проблема | Что действительно подтверждено | Исправление |
| --- | --- | --- |
| Сохранение устаревшего общего state | Более новый узел исчезает после сохранения старого снимка настроек | Атомарные узкие изменения с revision, без записи всего снимка из renderer |
| Повреждённый журнал Core | Startup бросает JsonException до открытия диагностического pipe | Доступная диагностика в degraded-режиме, блокировка мутаций и проверяемое восстановление |
| Ошибка записи ответа после действия | Тот же requestId повторно запускает component.execute | Durable intent до действия, outcome-unknown и сверка реального результата перед повтором |
| Быстрое включение DPI-профиля | UI выбирает standalone; менеджер отключает постоянный SCM-запуск установленной службы | Сохранять service mode; временный запуск выделить отдельной командой |
| Несколько подписок | Панель следует выбранному узлу, а удаление берёт subscriptions[0] | Один выбранный ID для панели и действий, подтверждение точной цели |
| Подтверждение DNS | Приняты 32/32 UDP-ответа из одного заголовка без объявленной answer section | Полный ограниченный разбор DNS; отдельные local readiness и upstream resolution |
| Подтверждение TUN | Вердикт protected возможен при пропущенной проверке Windows-маршрута | Доказательство интерфейса/маршрута либо честное unknown |
| Приватность диагностики | Синтетический секрет в пути DNS URL сохраняется после redaction | Структурное удаление секретных частей URL из export/logs |
| Доверие runtime | Изменённый пользовательский runtime выбирается по наличию файла | Защищённое размещение и проверка перед исполнением, GUI без постоянного повышения |
| Общий загрузчик компонентов | После заголовков нет общего/idle deadline; ошибка open оставляет body без cancel | Единый bounded downloader и cleanup всех ресурсов |
| Идентичность GUI/Core | Разрешённый по пути GUI EXE также имеет RunAsNode/inspect-возможности | Отдельный защищённый worker host, затем hardening GUI и проверка готового EXE |
| Достоверность UI | Будущий DNS/TG intent выглядит как ON; отсутствующий статус превращается в false | Отдельные intent и observed status; unknown/stale вместо фиктивного успеха |

Полный список с доказательствами, зависимостями и критериями приёмки: [prioritized-findings.json](prioritized-findings.json). P1 обозначает приоритет до stable, а не доказанный CVE или частоту отказа на установленной машине. Подтверждённого P0 этот аудит не установил.

В обновлённом backlog **32 задачи**: 26 исходных и шесть задач установщика R27–R32. **Пять исправлены в исходниках и проверены в пределах fixtures; native приёмка ожидается. 27 задач остаются открытыми.** R29 теперь регистрирует защищённый SYSTEM boot recovery до первого Disabled; R30 отменяет и завершает только проверенный собственный зависший worker и сохраняет возможность повторного восстановления. R32 исправляет потерю событий журнала и раннюю ошибку окна установки. Это разные scopes доказательств, перечисленные в receipts. Эти 32 записи включают архитектурные и измерительные задачи; это не 32 доказанных аварии приложения.

## Дизайн, который предлагается внедрить

Сохранён чёрно-белый стиль. Предлагаются шесть основных экранов, компактное окно, свёрнутая навигация и единая система состояний. Все 45 групп функций сопоставлены будущему интерфейсу; дополнительные настройки остаются доступными в соответствующих разделах.

Основные изменения: читаемые статусы, одна ясная главная операция, отдельная область VPN/щита/DNS/Telegram, раздельные выбранные и применённые настройки, одинаковые SVG и короткие анимации с reduced motion. В mini неизвестное состояние сначала предлагает проверить щит, а не выдаёт непроверенное подключение за факт.

- [Открыть интерактивный макет](design/preview.html) — действия инертны, службы не вызываются.
- [Обзор](design/screenshots/wide-overview.png), [DNS](design/screenshots/wide-dns.png), [mini](design/screenshots/wide-mini.png).
- [Дизайн-аудит и спецификация](design-audit.md), [токены](design/tokens-proposal.css), [сохранение функций](design/feature-preservation.json).

Действующим контрактом собранного кандидата остаётся корневой DESIGN.md. Макет и proposal CSS не импортируются в runtime. Проверка HTML при уменьшенном CSS viewport — не проверка реального Windows DPI. Реальная плавность foreground, hover подключённого щита и смешанные DPI мониторов остаются в приёмке реализации.

## Что даёт исследование рынка

Полезный ориентир — отделение GUI от владельца жизненного цикла и состояния, как описано в [архитектуре Mullvad](https://github.com/mullvad/mullvadvpn-app/blob/main/docs/architecture.md). Это архитектурный пример, не доказательство его превосходства или uptime Lagom. Исправления Windows-службы в [Clash Verge Rev 2.5.6](https://github.com/clash-verge-rev/clash-verge-rev/releases/tag/v2.5.6) помогают составить сценарии отказов, но не заменяют наши испытания.

Lagom объединяет компоненты с разными назначениями. Общая кнопка не должна скрывать их разные зависимости. NetworkCombinator в текущем коде планирует операцию и возвращает applied:false; его нельзя представлять готовым универсальным исполнителем. Если сохраняется требование работы **всех** функций без GUI, lifecycle VPN нужно отдельно перенести в службу и проверить на реальной Windows.

Исследование и первоисточники: [market-research.md](market-research.md), [market-sources.json](market-sources.json).

## Дальнейший порядок

[План реализации и выпуска](implementation-plan.md) задаёт зависимости, конкретные изменения и условия перехода между этапами: регрессионные тесты → persistence/службы → границы доверия → достоверные сетевые статусы → UI/производительность → автономность → установка, обновление и пилот.

Для автообновления 3.7.8/3.7.9 обнаружен отдельный **открытый P1 R31**: старый клиент запускает свой установленный helper, где нет нового защищённого recovery. Новый установщик требует verified boot registration и отклоняет такую старую stage. Нужен аутентифицированный bootstrap/передача управления до опасных изменений; простой выпуск нового Setup этого не решает. Реальный переход старых клиентов ещё не выполнен. Для 3.7.7 остаётся ограничение прежнего ключа: без соответствующего старого приватного ключа новая цепочка доверия не становится автоматически допустимой. Безопасный путь — однократная ручная миграция. Отключать проверку подписи ради автообновления нельзя.

Последний read-only снимок SCM от 30 сентября, 18:06 UTC показывает Core, SystemDoH, TelegramProxy и Zapret в Running/Auto, marker обслуживания отсутствует. [Receipt](installer/installed-services-latest-readback.json). Это установленные службы 3.7.9 в конкретный момент. Это не испытание новой 3.8.0 без GUI после reboot и не доказательство работы месяцами.
