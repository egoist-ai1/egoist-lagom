# Старое окружение: точный рецепт и диагностика запуска

Новый тестовый сценарий восстанавливает `~ RUNASADMIN` в HKLM/HKCU, registry views 64/32, только для канонического аутентифицированного старого GUI на одноразовом hosted runner. Это точный рецепт исторических исходников 3.7.8/3.7.9; полные source hashes и четыре строки каждого рецепта находятся в [receipt](receipt.json). Рецепт исходника не объявляется реконструкцией байткода подписанного NSIS.

Сценарий предварительно читает все четыре значения и отказывает при конфликте, затем проверяет фактическое значение и тип каждой записи. Остальные NSIS регистрации не восстановлены; запуск исходного Setup не заявляется. Диагностика токенов/запуска не заменяет обычный GUI и helper handoff.

Целевые проверки на рабочем исходнике: **26/26 PASS** в PowerShell 7.6.5 и **26/26 PASS** в Windows PowerShell 5.1, без ошибок и пропусков; actionlint exit 0. Сырые журналы сохранены без изменения. В частности, реальный физический host отказывается до lookup/write registry или восстановления служб.

На момент этого receipt новое восстановление ещё не исполнялось на hosted runner. GPU-дефект не объявлен исправленным. Физические registry/SCM/DNS изменения: **0**. Это проверка сценария, а не итоговая приёмка приложения.

После интеграции token/Win32 helper и записи исходного RUNASADMIN перед Core дополнительно прошёл полный целевой набор четырёх файлов: **30/30 PASS**, exit 0, без ошибок, пропусков и отмен. [Сырые результаты](integrated-final-30.txt) и [привязка к тестовым файлам](integrated-final-30.json) сохранены отдельно; предыдущие 26/26 остаются историческим результатом.
