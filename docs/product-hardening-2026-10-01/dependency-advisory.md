# Исправление npm audit: brace-expansion

CI run `36807040747`, исходный commit `9bf77129ccc2aeac741bf109b8ab6c9368fac558`, приложение 3.8.0. Реальный полный `npm audit --json` воспроизвёл **1 high**, агрегирующий три advisory одного пакета `brace-expansion 1.1.18`.

| Advisory | Ветка 1.x: исправление |
| --- | --- |
| [CVE-2026-102278 / GHSA-qhr7-859c-m2p7](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-qhr7-859c-m2p7), high | 1.1.20: ограничение глубины вложенности |
| [CVE-2026-102276 / GHSA-6j4f-fj2g-mc7p](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-6j4f-fj2g-mc7p), high | 1.1.19: исправление рекурсии разбора |
| [CVE-2026-102277 / GHSA-q2hr-2g5m-vwhr](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-q2hr-2g5m-vwhr), moderate | 1.1.21: ограничение повторного переписывания |

Нужна **1.1.21 для всех трёх находок**. Уязвимость возникает при передаче недоверенного glob-шаблона: возможны переполнение стека или задержка event loop. Эти advisory описывают отказ в обслуживании, не выполнение кода или утечку данных. Эксплуатация в реальных атаках здесь не исследовалась.

В проекте пакет находится только в dev-цепочке `@electron/asar 3.4.1 → glob 7.2.3 / minimatch 3.1.5 → brace-expansion`. Упаковщик использует фиксированный каталог приложения; `scripts/package-windows.mjs:100` копирует в runtime только `electron-log`, затем создаёт ASAR. Пакеты этой цепочки отсутствуют в 197 источниках текущей main source map и в двух локальных ASAR-кандидатах для 9bf. `npm audit --omit=dev` до исправления уже показал 0. Для проверенного состава приложения это находка сборочного инструмента; новый нативный runtime-компонент не требуется.

Изменён **только package-lock.json**: три поля `version/resolved/integrity` одной записи `brace-expansion`, 1.1.18 → 1.1.21. Прочие записи, `package.json`, MIT-лицензия и зависимости не изменены; overrides не добавлялись. Версия укладывается в существующий диапазон minimatch `^1.1.7`. Итоговый SHA-256 lock: `01BC98129BE8E07266C0BB20174C1C113B4CF021E5F7CE9C3AA467E9291F4706`.

После принятия lock реальные full/production audit на каноническом проекте: **оба exit 0, 0 находок**. Проверка Node 24.19.0: 19 обычных шаблонов сохранили результат; в шести изолированных дочерних процессах два старых переполнения стека воспроизведены, новая библиотека возвращает ограниченный результат. На одном malformed rewrite образце 1.1.18 заняла 3939 мс, 1.1.21 — 12,7 мс; это не общий benchmark приложения. Для чрезмерных шаблонов новые защитные пределы могут возвращать буквальный шаблон, что намеренно меняет старое поведение.

Сканер: официальный npm 12.2.0 с проверенной SHA-512 dist.integrity, совместимый с выбранным Node 24.19.0. Его версия не объявляется идентичной hosted CLI. Project `node_modules` этим worker не изменялись. Root затем выполнил locked `npm ci`; независимое чтение подтвердило установленную **1.1.21** и неизменный принятый lock. Root сообщил PASS main/preload/renderer/worker build и оба post-install audit с 0 находок; его private runtime не читался. Предупреждения устаревания `inflight/glob/rcedit` остаются в сборочных зависимостях. Нулевой audit означает отсутствие известных npm advisory в проверенном lock, а не отсутствие всех рисков.

Новый подписанный кандидат с обновлённым source binding и его native acceptance **ещё ожидаются**. Установленная система, SCM/DNS/Tasks/реестр этим worker не менялись; релиз не публиковался.

Принятые результаты audit, SHA-256 исходников проверок, библиотечные результаты, runtime inventory и ссылки первоисточников встроены в [dependency-advisory.json](dependency-advisory.json). Документ не подтверждает готовность всего релиза.
