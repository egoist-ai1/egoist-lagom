# Отказ исходного Setup 3.7.9: код 41

[Run 36834226795](https://github.com/egoist-ai1/egoist-lagom/actions/runs/36834226795), job `110279863127`, завершился при `/S` установке **исходной публичной 3.7.9**: Setup 206521508 байт, SHA256 `eb8db40e80201f5e9bf153368da8131325c0253bbc13a842c95f3f2725e04cc6`. [Принятые данные](native-466862-old379-failure/summary.json) и receipt содержат одну попытку старой установки, ноль завершённых проверок и GUI-запусков. Новый подписанный Setup 3.8.0 (`768953bfc01a64f1ea0c776246c0033c39c7c29acd2aafcbd48e08ad3c4e7b09`, source `466862cc00b36277460ccc94cb47f4df891ac14b`) ещё не выполнялся в этом job. Переход старого helper также не достигнут.

В [NSIS исходного тега](https://github.com/egoist-ai1/egoist-lagom/blob/d56eb9327fa75a88e91fae62b8d7ea3ed095dcf2/src/installer/setup.nsi#L239) единственный внешний `SetErrorLevel 41` находится на строке 243: ненулевой результат `PreInstall` → попытка `RollbackFailedInstall` → код 41 → Quit. Это до копирования payload (254) и регистрации Core (287; внешний код её отказа — 43). Код 41 скрывает внутренний exit/error PowerShell и не доказывает успех отката или отсутствие изменений в подготовительной фазе. Отказ начального CheckInstallSafety имеет внешний код 54, installer mutex — 48.

Локальный Setup проверен по точному опубликованному хешу. Из него **без исполнения** извлечён `$PLUGINSDIR/owned-cleanup.ps1`: 190567 байт, SHA256 `c7eca1981c0aa2eb237f1db29c0acfa2fe62a0756ef292efb97339815011f44e`. Его содержимое совпало с `d56eb9327fa75a88e91fae62b8d7ea3ed095dcf2:src/installer/owned-cleanup.ps1` после только нормализации BOM/CRLF; общий LF SHA256 `e00c18c62e9e6b50cfc915f26c77851c65c2b62cf3dda2219d11b276cd8b35ef`. Настоящий `Parser::ParseFile` дал **0 ошибок** на Windows PowerShell 5.1.26100.9168 и PowerShell 7.6.5. Таблица инструкций скомпилированного NSIS не декомпилировалась; привязка внешнего кода основана на исходном теге и проверенном embedded helper.

Причина внутри PreInstall **не установлена**. Старый `nsExec::Exec` (NSIS 84–89) возвращает только результат child; оба потока самого Setup в artifact имеют 0 байт. ZIP содержит восемь файлов, без старого журнала. Реальный путь helper — `%ProgramData%\EgoistShield\installer\upgrade-journal.json` (JSON lines, несмотря на расширение); старый branded status ошибочно указывает APPDATA. Отсутствие файла в artifact не означает его отсутствие на runner. `Write-Journal` также подавляет ошибку записи.

Первая проверяемая гипотеза — старый DNS snapshot: embedded helper 1577–1586 выбирает активные uplink adapters, а 1602/1604 требует отдельного DNS client row для каждого IPv4/IPv6 семейства с `ErrorAction Stop`. Тот же запрос ранее дал настоящий `CmdletizationQuery_NotFound` для IPv4 интерфейса 9 на hosted Windows; [исходный stderr](native-first-run/source-pre-install.stderr.txt) и [before/after](native-first-run.md) сохранены. Это объясняет возможный отказ старого Setup на данном образе, но новый receipt не содержит adapter inventory, внутреннюю ошибку или журнал, которые подтвердили бы совпадение причины. Провайдер CIM, ошибка snapshot/файлов, блокировка или повторный safety отказ тоже ещё не исключены.

Минимальная следующая диагностика принадлежит root:

1. На том же **disposable Windows image**, в отдельном ограниченном read-only child Windows PowerShell 5.1, снять адаптеры по точному фильтру оригинальной функции и выполнить её IPv4/IPv6 DNS queries. Сохранить индекс/GUID/status, наличие row, `FullyQualifiedErrorId`, сообщение и elapsed; timeout/provider failure остаются Unknown. Никаких Set-DNS, изменений bindings, отключения адаптеров или импорта всего helper.
2. После отказа неизменённого оригинального Setup сразу сохранить ограниченный plain-path старый `upgrade-journal.json` сырыми байтами и факт наличия/размеры `network-baseline.json`, `service-backup/manifest.json`, marker. Последний stage отличит отказ до service snapshot, между ним и DNS snapshot, либо позже. Снять after network/foreign-registration fingerprints; в текущем artifact они не подтверждены.
3. Если данных всё ещё недостаточно, отдельный guarded disposable diagnostic job может захватить stdout/stderr **точного извлечённого оригинального** PreInstall, с исходным SHA и сетевыми readbacks. Это отдельный диагностический запуск с возможными подготовительными изменениями; он не заменяет запуск оригинального Setup и не считается установкой/обновлением PASS.

Здесь выполнены только чтение проектных данных/оригинального EXE, извлечение в собственный work и статические проверки. Production, CI и физические SCM/DNS/tasks/registry/UI не изменялись. [Машинный отчёт](old379-setup41-analysis.json) фиксирует источники, хеши и границы вывода.
