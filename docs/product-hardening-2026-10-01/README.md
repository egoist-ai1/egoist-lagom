Пересборка и повторная нативная приёмка новых подписанных байтов обязательны перед установкой и публикацией.

## Что изменено

- Core различает отсутствующий, повреждённый и недоступный файл. Конкурентное чтение и атомарная замена используют ограниченный набор общих блокировок. Повреждённый журнал или конфигурация разрешают диагностику и блокируют новые изменения.
- Намерение операции сохраняется до внешнего действия. Неизвестный исход после аварии не исполняется повторно вслепую. Подтверждённый откат VPN восстанавливает прежнее намерение; поздний откат не отменяет более новое выключение.
- Добавлена отдельная, явно устанавливаемая `EgoistShieldVpn`. Она использует защищённый снимок выбранного сервера и работает через Windows service без GUI. Снимок, производная конфигурация и служебные результаты закрыты для обычных пользователей. Создание дочернего процесса и помещение в job теперь атомарны.
- Закрытие приложения завершает временный runtime и сохраняет фоновую службу. Одновременные TUN запрещены. Включение/остановка службы требуют свежего результата; Unknown сохраняет ограничения. Временно неготовая фоновая служба продолжает владеть маршрутом и не разрешает конфликтующие изменения.
- Локальная готовность, внешний запрос и подтверждение маршрута разделены. Фоновый SOCKS listener не выдаётся за Windows system proxy. Неподтверждённый TUN остаётся «требует проверки».
- DNS UDP/TCP и HTTP CONNECT/TLS получили строгую проверку пакетов, ограниченные бюджеты, отмену и очистку ресурсов. Устаревшая проверка не заменяет состояние нового экземпляра.
- Установка использует окно обслуживания и сохранение намерений. Private Runtime/Vpn и TelegramProxy получают закрытый ACL до копирования. Восстановление VPN проверяет собственный процесс и listener, а не только SCM Running. Полный uninstall удаляет собственный VPN-снимок после подтверждения отсутствия службы.
- Добавлена передача управления от старого установочного worker новому с ожиданием освобождения lease и завершения старого watchdog. Реальный переход подписанной 3.7.9 ещё требует отдельного установочного запуска.
- GUI работает как `asInvoker`; Electron 44.5.1 и 73 файла проверены по официальному SHA256. ASAR integrity, fuses и авторизация Core закрывают внешние scripts, Node startup injection и GUI debug/child argv. Packaged приложение игнорирует test/mock environment.
- Обычный GUI выполняет пять DNS-операций через авторизованную Core, без требования запускать интерфейс администратором. Недоступная или неподтверждённая Core блокирует действие до изменения сети. Настройки маршрутизации, DNS, TUN и правил используют реальные API и проверку ревизии; конфликт записи сохраняет пользовательский черновик.
- Исправлена реальная ошибка Setup43: повышенный администратор не мог назначить SYSTEM владельцем файлов. Core выбирает только доступного доверенного владельца, задаёт private ACL до записи данных и проверяет результат. Чтение открытого service.log использует совместимый sharing, отмену и ограничение размера.
- Исправлен hover щита: чёрная галочка сразу скрывается, белый power icon остаётся чистым. Уточнены контраст, focus и motion. Список серверов ограничен 60 строками на страницу, поиск охватывает весь набор. Управление фоновым VPN показывает выбранный snapshot и запрашивает подтверждение установки.
- Координатор использует монотонное время и конечные очереди. Диагностический plan без исполнителя больше не сообщает, что Windows изменена или подключение проверено. Автообновление учитывает наблюдаемую фоновую службу и ждёт незавершённые операции.

## Следующий этап выпуска

Подготовлен защищённый сценарий настоящей установки, GUI/UIAutomation, Core/Telegram SCM, восстановления, upgrade и uninstall на одноразовом Windows runner. До его результата релизная готовность не объявлена. Также отдельно требуются старый подписанный update helper, ordinary-token GUI, native DNS/TUN и reboot. Многомесячный uptime требует фактической эксплуатации; короткий стресс его не доказывает.

Для старого helper подготовлен [отдельный сценарий](legacy-harness.md), проверенный 5 guard/verification тестами. Новая подписанная release-manifest дополнительно связывает точный source commit и SHA256 исходного package-integrity.json; подмена даже форматирования integrity после подписи отклоняется. Сам ключ остаётся локально. Native legacy job получает настоящие подписанные assets из draft, а не тестовый ключ; публичное обнаружение latest-feed этим способом ещё не проверяется.

Действующий локальный release key найден и совпадает с текущим authenticated trust registry; подпись не является блокером. Переход 3.7.7 без принятого старого приватного ключа требует однократной ручной миграции. Для 3.7.8/3.7.9 нужна проверка настоящей принятой цепочки; отключение проверки подписи не предусмотрено.

Реальный verifier установленной 3.7.9 уже прошёл [15 проверок подписей, адресов и хешей](auto-update-compatibility.md). Полный автоматический переход требует успешного старого helper и доступного опубликованного feed. В старых версиях проверка обновлений работает при запущенном GUI; активный VPN может откладывать установку. Оригинальная подписанная 3.7.8 сохранена и передаётся в тест неизменной [как локальное поколение](legacy-local-transport.md); её наличие не объявляется доказательством ранее опубликованного stable feed.

Отдельный новый hosted тест выявил [разницу служебного флага наследования Windows](core-owner-atomic-acl-capture/README.md) после 256 атомарных замен: владелец и все разрешения остались прежними, добавилась только метка AI. Сравнение с исходной реализацией и native ReplaceFile проверяет эту причину; production-политика private ACL не ослабляется.
