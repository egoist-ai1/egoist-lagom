Гипотеза об утраченном оригинальном RUNASINVOKER **не подтвердилась**. В исходниках установщика записан `~ RUNASADMIN` для точного `$INSTDIR\EgoistShield.exe` в HKLM/HKCU, Registry64/Registry32. После этих записей и shortcut flags NSIS вызывает `InstallCoreService`, затем `PostInstall`. Источники:

Scoped read-only проверка установленной физически 3.7.9 дала тот же аутентифицированный GUI hash, `~ RUNASADMIN` во всех четырёх Layers и отсутствие `__COMPAT_LAYER` в process/user/machine environment. Реестровые значения не менялись, приложение не запускалось. Git recipe и физический readback согласуются, но это не декомпиляция подписанного NSIS bytecode и не доказательство полного восстановления ARP/shortcuts/uninstaller.

Восстановление исходного RUNASADMIN допустимо как явно записанное дополнение fixture. **Не доказано, что оно устраняет GPU отказ.** Применять RUNASINVOKER, изменять manifest или отключать sandbox ради «успешной оригинальной проверки» нельзя. Исторический [первичный reproducer Electron Builder на Windows Server](https://github.com/electron-userland/electron-builder/issues/5439) поддерживает гипотезу о сочетании requireAdministrator и token/context, но использует Electron 11 и не подтверждает текущую причину. Текущий [скрипт GitHub image](https://raw.githubusercontent.com/actions/runner-images/main/images/windows/scripts/build/Configure-BaseImage.ps1) задаёт ConsentPromptBehaviorAdmin=0; он не доказывает фактический EnableLUA либо token в нашем прогоне.

Реализован отдельный **`Invoke-LegacyLaunchDiagnostic`** в новых `tests/windows-legacy-launch-diagnostic.cs/.ps1`. Импорт `-LibraryOnly` сохраняет переменные родительского harness. Параметры: `InstalledGuiPath`, `ExpectedGuiSha256`, `ExpectedOldVersion`, `WorkRoot`, `EvidenceDirectory`, `ExpectedSourceCommit`; результат — один receipt path.

Помощник до обращения к продукту требует настоящий disposable GitHub-hosted Windows/admin context. Затем проверяет фиксированные original hash/size/version и canonical Program Files path; evidence остаётся внутри WorkRoot/RUNNER_TEMP. Он читает UAC, Layers и current/linked/restricted token proof, вызывает настоящий `CreateProcessAsUserW` с `CREATE_SUSPENDED` и сразу записывает `Marshal.GetLastPInvokeError`. Любой созданный процесс удерживается собственными handles/job и завершается до исполнения; `ResumeThread` отсутствует. Исходный EXE удерживается read lock и проверяется по SHA256 до/после. SCM, сеть и registry write API не используются.

Это **диагностика выбранных токенов**, а не захват исторического Chromium GPU lastError. Restricted sample не равен Chromium token/AppContainer/mitigation policy. Успешное suspended creation подтверждает только создание процесса до исполнения; поля `acceptance=false`, `actualChromiumGpuErrorCaptured=false` обязательны. Ошибки 740/1314/5 нужно читать с учётом конкретного stage и sample, согласно [контракту Microsoft CreateProcessAsUserW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessasuserw).

Проверено локально: SDK 10.0.401 build — 0 compiler warnings/errors; managed self-test — 20 checks, nativeCalls=0; Node focused — 4 passed/0 failed/0 skipped; PS5.1 и PS7.6.5 parse — 0 errors, import/physical-host refusal проверены. Store effects первоначального SDK first run не измерялись; удаление сертификатов не выполнялось. Локальных suspended попыток с продуктом, установки, workflow dispatch и acceptance запуска не было.

Если GUI снова падает, сохраняем отказ: дальнейший честный путь — совместимая одноразовая Windows desktop x64/UAC среда с настоящим host identity.
