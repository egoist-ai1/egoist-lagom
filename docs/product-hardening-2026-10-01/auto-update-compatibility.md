## Native acceptance

Независимый публичный readback [workflow 36811362434](https://github.com/egoist-ai1/egoist-lagom/actions/runs/36811362434) в **2026-10-01T03:57:28.434Z** подтвердил **completed / failure**, head SHA `3dae559124015b74dfeaabb12e46621cfd6d4cdc`. `test` прошёл; `signed-candidate`, `legacy (3.7.8)` и `legacy (3.7.9)` завершились ошибкой. Это не pending run и не успешно выполненный upgrade.

Точные причины ниже получены из CI diagnostics, которые проверил parent; этот участок самостоятельно прочитал статусы/steps через публичный API, не запускал native Setup и не скачивал CI logs:

- Fresh Setup: exit **43**, `InstallCoreService`; GUI/DNS/TUN acceptance не достигнут.
- Legacy 3.7.9: общий CIM `Win32_Service` query с лимитом 5 секунд завершился timeout **до Setup**; успешный handoff не доказан.
- Legacy 3.7.8: API старого публичного tag вернул **404 до Setup**. По сведениям parent, оригинальные подписанные Setup/manifest сохранены в проекте; они не проверены этим аудитом.

Оригинальные установленные `invoke-final-silent-reinstall.ps1` и `ModernInstaller.exe` только прочитаны и хешированы. Их SHA сохранены в JSON, запуска не было. Повторная native проверка должна относиться к точным принятым байтам Setup и commit; новый успешный запуск нельзя предполагать заранее.

В исходниках **реальной 3.7.9** автоматическая проверка выполняется только при работающем packaged процессе приложения и включённой настройке autoUpdate. Первый check планируется через 10 секунд, обычный следующий — через 24 часа. Retryable failures используют 5/15/60/180 минут и 24 часа. Установка требует явного `connected === false`, свободного coordinator, отсутствия boot recovery и component update; занятый VPN откладывает её на 15 минут. Поэтому постоянно подключённая старая 3.7.9 может постоянно откладывать установку. Работа установленных сетевых служб без GUI и расписание updater — отдельные контракты. Updater daemon при закрытом процессе в этом старом коде нет. Настоящие пользовательские настройки и сохранённый anti-rollback state не читались.

1. Публичные latest API и stable feed должны указывать на один новый опубликованный stable tag. Сравнить **фактические** asset name, URL, size и GitHub digest с подписанным manifest.
2. Прочитать опубликованные stable/release metadata и подписи; сравнить байты с принятым кандидатом и проверить их старым verifier с неизменным bundled trust.
3. Скачать настоящий публичный версионный Setup в собственный cache проверки, подтвердить размер, SHA-256 и SHA-512.
4. Получить PASS native fresh install и original-helper upgrades на точных финальных Setup/commit; для 3.7.8 подтвердить собственный оригинальный bundle, не заменять его другим клиентом.
5. На acceptance host проверить настоящий цикл старого updater до новой установленной версии и readback сохранённых настроек/служб. Этот read-only аудит такого цикла не выполнял.
