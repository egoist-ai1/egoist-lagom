# Доступные настройки маршрутизации VPN

В «Настройках» добавлен раскрываемый раздел «Маршрутизация VPN». Он открывает существующие возможности бэкенда через настоящие команды сохранения. Система дизайна, чёрно-белая палитра, навигация и мини-щит сохранены. В recovered renderer изменено только место включения `RubyNetworkSettings` в `Dp`; компоненты и стили находятся в `CompactRuby.jsx` и `compact-surfaces.css`.

## Что доступно

| Настройка | Значения production-контракта | Поведение |
|---|---|---|
| Маршрут VPN | `global`, `selected` | Остальной трафик через VPN либо напрямую; явные правила и исключения ядра проверяются раньше. |
| DNS VPN | `auto`, `secure`, `system`, `custom` | Автоматический выбор, встроенный профиль, DNS Windows либо собственный HTTPS DoH. |
| TUN временного VPN | `useTunMode: boolean` | Захват системного трафика и применение правил процессов. Временный TUN требует административных прав. Фоновая служба всегда использует TUN. |
| Домены | `{id, domain, mode}` | Обычный домен и поддомены, нормализация Unicode в punycode. Без URL, пути, IP, масок и специальных префиксов в новом редакторе. |
| Процессы | `{id, process, mode}` | Имя `.exe`-файла Windows без пути и масок; применяется в TUN. |
| Действие правила | `vpn`, `direct`, `block` | Через VPN, напрямую или блокировать. Добавление, изменение, удаление, перемещение выше/ниже. |

Системный DNS не обозначается зашифрованным и не обещает отсутствия утечек. Встроенный DNS sing-box использует HTTPS через VPN; встроенные IP DNS в Xray не дают такой гарантии. Для собственного DoH интерфейс принимает только полный HTTPS URL без credentials, управляющих символов и фрагмента. Порт и query сохраняются; bootstrap имеет отдельный путь.

Правила процессов проверяются раньше доменов; внутри типа сохраняется порядок, действует первое совпадение. Новый UI ограничивает домены 253 символами, имена `.exe` 260 символами, списки 256 правилами каждого типа и показывает по 24 строки. Специальные существующие engine-токены не переводятся в другой формат скрытно. Контракт бэкенда описан в [rules-contract.md](rules-contract.md); согласованное сопоставление обычных доменов проверяет отдельный сетевой аудит.

## Сохранение и конфликты

Настройки сохраняются через `egoistAPI.state.patchSettings(patch, expectedRevision)`. В patch попадают только изменённые поля. Правила используют `state.get()` → изменение нужной строки по стабильному ID → `state.patchRules(patch, expectedRevision)`; patch заменяет только выбранный массив. Чужие узлы, подписки, настройки и другой тип правил сохраняются. `state.set` и привилегированные обходы не используются.

Успех требует ответа `{ok:true,state}` с подтверждённой ревизией и массивами правил. Отказ, ошибка записи, неизвестный ответ или конфликт не показываются сохранёнными. Конфликт сохраняет черновик и предлагает взять актуальные значения либо явно оставить свой черновик и заново сохранить. Автоматического повторного перезаписывания нет. Изменение правил при открытом редакторе требует закрыть его и повторить действие по актуальному состоянию.

Изменения не переписывают активный runtime или защищённый снимок фоновой службы. Нужны переподключение временного VPN либо отдельное действие **«Применить сервер и правила»** в разделе VPN. Это создаёт новый снимок и перезапускает службу; установка использует production-контракт `serviceInstall(nodeId)` со строковым ID. Запуск приложения при входе в Windows остаётся отдельной настройкой.

## Доступность и устранённые дефекты

Редактор правил использует нативный HTML `dialog`, начальный фокус на поле, удержание Tab/Shift+Tab, Escape и восстановление фокуса на кнопку открытия. При неизвестных правилах Save и поля недоступны, Cancel/Escape работают. Во время сохранения повторные команды блокируются.

Проверка в Chromium обнаружила и исправила неоднозначные имена select, выход Tab из редактора, устаревшую локальную ревизию после завершения сохранения правил и перекрытие поля DNS уведомлением. Сообщения новых действий показываются внутри раздела. Остальные уведомления занимают отдельную строку под рабочей областью, сохраняют роль live status и кнопку закрытия; они не накладываются на навигацию и содержимое.

Фактически проверенные имена в Chromium accessibility tree:

| Элемент | Роль / имя |
|---|---|
| Раскрываемый раздел | `DisclosureTriangle`: `Маршрутизация VPN Режим соединения, DNS и правила`; изначально collapsed, focusable. |
| Маршрут | combobox `Режим маршрутизации VPN`; вариант `По правилам · остальное напрямую` → `selected`. |
| DNS | combobox `DNS соединения VPN`; вариант `DNS системы` → `system`. |
| Сохранение | button `Сохранить настройки VPN`. |
| Добавление процесса | button / dialog `Добавить правило процесса VPN`. |
| Поле процесса | textbox `Процесс для правила VPN`. |
| Действие | combobox `Действие правила VPN`; `Через VPN` → `vpn`. |
| Редактор | buttons `Закрыть правило VPN`, `Отмена`, `Сохранить правило`. |
| Фоновый VPN | switch `VPN без приложения (TUN)`; установка `Установить и включить`, повторное применение `Применить сервер и правила` → подтверждение `Применить`. |
| Остановка/удаление | switch с текстом `Остановить фоновый VPN`; `Удалить службу VPN` → подтверждение `Удалить`. |

Путь для отдельной hosted native проверки: мини-щит **Настройки** → основной раздел **VPN** → обычный **Импорт** собственного SOCKS-узла → **Настройки** → раскрыть **Маршрутизация VPN** → `selected` + `system` → **Сохранить настройки VPN** → добавить правило процесса `LagomVpnNativeProbe.exe` / «Через VPN» → **Сохранить правило** → **VPN** → установить или явно применить фоновую службу. Проверка Windows UIA, физического TUN и независимых canary-проб этим отчётом не заявляется.

Проверены реальные извлечённые UI helpers, production schema/preload/StateStore, CAS, сохранение после записи на NTFS, 100 последовательных подтверждённых изменений и 40 явных конфликтов; полный журнал [ui-network-tests.txt](ui-network-tests.txt). Это целевой набор, общий release CI принадлежит основной задаче.

**20 состояний/скриншотов и 11 групп взаимодействий** в Chromium 151.0.7922.34 прошли без renderer-ошибок, внешних запросов, горизонтального переполнения и перекрытых центров видимых активных контролов. Проверены route/DNS/TUN save, punycode, порядок и точное удаление ID, ошибки DoH, pending, запись с отказом, конфликты без повторного overwrite, Unknown в открытом редакторе, отдельное применение снимка, HUD на ширине 1060/600/400, узкий редактор, browser-emulated 200% и reduced motion.

Chromium использует явно обозначенные инертные IPC-fixtures только для интерфейса. Системные DNS/SCM/registry, установленные службы и реальные сетевые маршруты не менялись.
