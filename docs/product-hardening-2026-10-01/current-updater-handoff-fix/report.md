# Current updater preparation handoff fix

The ordinary outer PowerShell dispatcher previously returned exit zero immediately after launching elevated preparation, with `elevatedPreparationPending=true`. The desktop updater treated that result as a ready handoff and scheduled application exit, even if the elevated preparation later failed before UI readiness or worker dispatch.

The outer dispatcher now requests `-PassThru` and waits up to 300 seconds on that exact held preparation process. It propagates the actual preparation exit code. Exit zero follows completion of the inner dispatcher, including its existing UI-ready check, worker dispatch and handoff signal write. The outer receipt uses `elevatedPreparationCompleted=true`. It does not accept a pre-existing signal as proof and does not use `Start-Process -Wait`, which could wait for the subsequent worker/installer tree. The held process object is disposed by the outer dispatcher.

Preparation timeout fails readiness and leaves the current application open. It does not kill an elevated process that may have begun the maintenance handoff. After the updater has an actual helper PID or observes its `spawn` event, failure handling retains the verified installer and integrity manifest. A failed native spawn with no child, or a failure before spawn, retains the previous candidate cleanup behavior. The automatic continuation checks still apply before helper launch; they do not recall an already committed helper.

Regression evidence: three original source-extracted preparation checks failed before the fix. The ordinary branch returned 0 when its actual harmless preparation child exited 7; the other failures covered the premature pending-success receipt and the absent bounded wait. After the fix, all three passed. Additional regressions use actual harmless child-process creation and real file hashes to verify retained inputs after a child exits with failure, cleanup when native process creation fails, and cleanup before spawn when readiness is busy.

Final targeted suite: 35 passed, 0 failed, 0 skipped across the new preparation tests and existing final-silent-reinstall, version-handoff, automatic cancellation, scheduler, download-retry and stream tests. Existing tests were not edited. Main/P2 reports were not changed by this P1 fix. The previous updater review's remaining P1 section describes the pre-fix state and is superseded by this report.

Limits: tests parse the actual PowerShell source and execute its extracted branch/functions. Elevation is replaced by a task-owned ordinary PowerShell child; this is not real UAC, installer UI, Setup, SCM, restart or public-release acceptance. The parent must verify actual elevated preparation and native handoff against the sealed current package. A process may still progress after the five-minute readiness deadline; retained inputs prevent cleanup from interfering with that committed attempt. Original historical helpers and trust pins were not altered.
