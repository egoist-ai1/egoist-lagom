# Проверка интерфейса Lagom 3.7.9

29 сентября 2026 года проверен установленный production EXE после установки `8f72194698fa4523bcc4243d919c506d`: версия 3.7.9, Electron 44.4.5, Chromium 152.0.7977.130. Это настоящий процесс 47336, созданный 16:07:26.0224761 UTC. В установленном приложении IPC, ответы служб и пользовательские данные не подменялись.

[Сводная приёмка](installed-3.7.9-native-acceptance.json) содержит73 наблюдения layout,49 успешных проверок и2 намеренно пропущенных публичных crop при увеличенном масштабе. Ошибок renderer, обнаруженных перекрытий видимых интерактивных целей, целей меньше24CSSpx и горизонтального переполнения —0. [Подробные измерения](installed-3.7.9-native-details.json) сохраняют наблюдаемые boolean состояния служб, размеры, навигационные интервалы и фоновые frame-сэмплы.

## Метод и ограничения native capture

Привязка проверяет PID, время рождения, путь EXE, версию, target ID/URL и установленный main hash. Размеры задавались документированными API настоящего Electron-окна, zoom — `webContents.setZoomFactor(2)`. Viewport/media/visibility/config/IPC emulation не применялась. Native background throttling временно отключался и восстановлен. Снимки получены `capturePage(rect,{stayHidden:true,stayAwake:true})`; hidden/unfocused guard проверялся до и после. См. [capturePage](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts), [background throttling](https://www.electronjs.org/docs/latest/api/web-contents#contentssetbackgroundthrottlingallowed) и [чтение ASAR обычным Node API](https://www.electronjs.org/docs/latest/tutorial/asar-archives#node-api).

Настоящий hover получен документированным `page.mouse.move` у конкретного renderer, без OS-курсора, клика по службе, bringToFront и принудительного CSS pseudo-state. После каждого движения проверялось, что native окно осталось скрытым и без фокуса. См. [Playwright Mouse](https://playwright.dev/docs/api/class-mouse#mouse-move).

Скрытая native отрисовка может задерживаться или показывать промежуточный кадр после500мс wall-clock ожидания. Первый hover crop был бледным; отдельная попытка, предполагавшая завершение перехода строго за500мс, не прошла. Единственный последующий ограниченный read получил конечный белый выключатель на тёмно-сером фоне после одного дополнительного штатного native capture/wait. Исходные неуспешные наблюдения сохранены в сводке; они не скрыты и не выдаются за успешный первый проход. Это ограничение скрытого окна, а не измеренная задержка видимого окна или гарантия foreground FPS.

Первый полноразмерный проход выявил две ошибки самого audit harness: About активировался без предварительного фокуса на вызывающей кнопке, а геометрия выбора сервера считывалась до завершения его modal entry и считала покрытые фоном кнопки. После исправления только harness повторная активация с фокусом и ожидание настоящего диалога прошли на всех размерах. Продукт после freeze не менялся.

[Pixel-счётчики](installed-3.7.9-paint-presence.json) фиксируют наличие растрового содержимого тела всех шести страниц при2000×1100:43264–67421 пикселей ярче48 в общей области1619800px. Это подтверждает присутствие paint, а не правильность каждого пикселя. Исходный41 runtime имел ограничения скрытого захвата; это не означает, что видимое окно было чёрным.

Фоновые rAF и интервалы навигации описывают конкретный hidden renderer с временно отключённым throttling. Они не доказывают DWM/GPU/foreground FPS и плавность на всех компьютерах. Нативные Windows maximize/minimize не выполнялись; большой layout не является проверкой maximized-состояния. UI-проверка не доказывает перезагрузку Windows или месяцы непрерывной работы; проверки фоновых служб и восстановления находятся в отдельных отчётах.
