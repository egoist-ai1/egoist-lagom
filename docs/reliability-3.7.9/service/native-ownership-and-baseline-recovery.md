В Core 3.7.9 заменено частое чтение владельца Telegram-порта через PowerShell/CIM на прямое чтение Windows API. Проверки принадлежности остались обязательными: точный путь SCM wrapper, PID и время создания процесса, проверенная цепочка родителей, действующий listener, TCP connect и второй свежий snapshot. Чужой порт возвращает Conflict; недоступные метаданные возвращают Unknown и не разрешают восстановление службы.

Измерения выполнены на реальных работающих службах 29 сентября 2026 года, по три полных проверки каждого сценария. Inspector собран из исходников 3.7.9 на SDK 10.0.401 / runtime 10.0.12; в момент замеров установлена 3.7.8. Проверки только читали SCM, TCP и метаданные процессов. Старый путь во всех трёх замерах успешно вернул Responsive в пределах общей границы 8 секунд. Поэтому утверждения, что он неизбежно возвращал Unknown или был постоянно неисправен, этим измерением не подтверждены.

Исходные результаты: [старый путь](legacy-whole-probe.json), [принадлежащий порт](native-owned-probe.json), [Relay](native-foreign-probe.json), [свободный порт](native-missing-probe.json). Это короткое измерение конкретного компьютера; оно не доказывает такую задержку на каждом Windows host или при любой нагрузке.

Новый collector использует QueryServiceStatusEx, GetExtendedTcpTable для IPv4/IPv6, Toolhelp и ограниченные process handles для пути и времени создания. Он не читает command line, конфигурацию proxy или секреты. Существуют ограничения количества TCP rows, выбранных endpoints, глубины ancestry и размера таблиц. На reader допускается только одна незавершённая native-задача; результат после timeout не переиспользуется как здоровый. Общая граница проверки Core остаётся 8 секунд. Синхронный вызов Windows нельзя безопасно оборвать внутри ядра; если он задержится, Core вернёт Unknown и не создаст очередь новых зависших чтений.

Для интерфейса добавлен отдельный режим `EgoistShield.Service.exe --telegram-listener-snapshot --port <1..65535>`. Он исполняется до создания service host и не изменяет службы, настройки или файлы. Snapshot ограничен тремя секундами; JSON — 60 KiB при границе GUI 64 KiB. Переполнение возвращает Unknown целиком, сохраняя запрет на частичное доказательство здоровья. `ipv4` и `ipv6` содержат состояние и настоящий PID/name/birth выбранного listener. При смеси принадлежащего и чужого endpoints выбирается именно конфликтующий процесс. Произвольный service/path, дополнительные режимы и неверный порт отклоняются. Для здорового состояния GUI проверяет два свежих чтения с одинаковыми root и owner PID/birth и локальный TCP. Доступность удалённого Telegram этим не подтверждается.

В установленной **3.7.8** дополнительно проведены два реальных отказа без открытого интерфейса. Каждый helper сначала проверял точный исполняемый файл, SCM ancestry, PID/birth и удерживал process handle; завершался ровно один дочерний процесс. Ручной перезапуск, исправление DNS и запуск интерфейса для восстановления не использовались.

Независимое чтение Core даёт version 3.7.9.0 и SHA-256 `5A2FD51C4E907BC50B8C1DAC352404EF12341CC401E9AA3A3E0D7EEADC2683B8`. Этот этап содержит Electron 41.10.4; окончательная пересборка с Electron 44 и её живые проверки записываются отдельно владельцем релиза. C# и проверенный Core не изменяются для этой замены runtime.

Настройки Auto/LocalSystem, recovery и enrollment подтверждены чтением в [конфигурации 3.7.8](../../reliability-3.7.8/service/live-autostart-configuration.json); это проверка настроек загрузки, а не выполненной загрузки. Основные supervision, DNS transactions, ownership, intent и bootstrap изменения 3.7.8 описаны [в предыдущем отчёте](../../reliability-3.7.8/service/README.md) и сохранены. В частности, disconnected-present NIC сохраняет свою GUID identity и участвует в собственной DNS миграции; физически отсутствующий ранее управляемый NIC откладывает смену IP, чтобы не удалять ещё используемую регистрацию. Изменённые извне family settings и недостаток адресов ранее управляемого семейства блокируют автоматическую замену.

Fault helpers предназначены для одной заранее проверенной цели и остановятся при изменении идентичности, конфликте порта, открытом GUI или чужой настройке. Если естественное восстановление не случилось, автоматического rescue в helpers нет. Оператор сначала проверяет принадлежность SCM регистрации, сохранность config и отсутствие чужого listener. Затем допустим один Start принадлежащей остановленной службы; при Running и доказанном локальном зависании — Stop/ожидание Stopped/Start только этой регистрации. Внешняя DNS ошибка при живом локальном handler не является основанием для этого действия. Удаление tree, reinstall и DHCP reset этим тестом не выполняются.

Актуальный Core-only helper допускает оба доказанных исходных состояния Relay: присутствующий процесс с точным path/PID/birth и listener 1443 либо полное отсутствие и exact-path процессов, и listeners 1443. Во время теста сохраняется именно исходное состояние. Чужой или неоднозначный owner и недоступные метаданные блокируют допуск. [Контракт helper, текущий SHA-256, поля receipt и границы проверки](core-fault-helper.md) описаны отдельно; исторические измерения с присутствующим Relay остаются измерениями своего этапа.
