# Загрузки, release URL и происхождение IPC

Исправлены исходники R11, R21 и R22 поверх `5d0d58b44076843e639723ef267e7b8d2605e481`. Доказательства относятся к функциям продукта и изолированным файлам/соединениям. Установка приложения, системные службы, DNS, публикация и ключи доверия этим этапом не изменялись.

До изменения настоящий `fetch` и общий загрузчик оставляли операцию pending через 320 ms при сокращённом сроке заголовков 60 ms. После заголовков срок уже не действовал. Ошибка открытия файла оставляла тело ответа без отмены. Production validators принимали чужой `file:` host, credentials и порт 8443. Исходные результаты сохранены в `transport-baseline-download.json`, `transport-baseline-canonical.json` и `transport-baseline-ipc.json`; ожидаемый commit старого audit-harness в них исторический, фактический старт этого этапа — указанный выше commit. SHA-256 прочитанных файлов сохранены.

Общий `downloadFileWithProgress` теперь ограничивает заголовки 60 секундами, простой тела 15 секундами, всю операцию с повторными попытками 10 минутами и полученное тело ответа 512 MiB. При наличии размера asset он должен совпадать с полученными байтами. Данные записываются в отдельный случайный файл через exclusive open; частичная запись дописывается, файл синхронизируется и закрывается перед rename. Ошибка, отмена, недостоверный размер и неудачное переименование сохраняют прежний файл. Cleanup удаляет только созданный этой попыткой stage; настоящий EEXIST не удаляет чужой файл. Ошибка освобождения reader не подавляет исходную ошибку записи и закрытие файлового handle. Прогресс 100% выдаётся после публикации файла. Проверка SHA-256 архива в callers по-прежнему предшествует публикации runtime.

`fetchWithRetry` умеет вручную проверять каждый redirect до запроса. Release helpers требуют HTTPS, допустимый host, отсутствие userinfo, нестандартного порта и фрагмента. Первичный архив должен иметь GitHub release path, а CDN сохраняет необходимые подписанные query-параметры. Между origins удаляются Authorization, Cookie и Proxy-Authorization. Лимит — четыре перенаправления. Manifest принимает ровно каноническую строку URL; Ed25519, root pinning, отзыв ключей и anti-rollback не ослаблялись. Parent-owned DesktopUpdater подключён к этому transport guard; интеграционный тест запускает его настоящую функцию загрузки с настоящим shared transport.

IPC разрешает ровно установленный `index.html`, WebContents главного окна и его main frame. Чужие hosts, UNC/localhost alias, соседние документы, подкаталоги, encoded separators, NUL, query/hash и двусмысленные dot segments отвергаются. Главное окно привязывается до `loadFile`. Это проверка URL/event contract; фактическая UNC-навигация не запускалась.

RuntimeInstaller проверяет разрешённый корень до recovery, записи и загрузки. Высокопривилегированный сценарий записи/выполнения пользовательского runtime блокируется согласованным `prepareRuntimeInstallRoot`; его настоящую проверку token/ACL покрывает отдельный этап identity. Непривилегированный runtime update получает точный URL ожидаемого upstream repository/tag/asset и безопасное имя ZIP. Эта интеграция не реализует новый привилегированный Core runtime updater.

Финальная адресная проверка: **94/94 PASS, 0 skipped**, семь файлов тестов; полный вывод — `transport-tests.txt`, сводка и hashes — `transport.json`. В неё входят настоящий HTTP stall/drip/cancel, overflow, actual EEXIST, short writes, rollback publication, контролируемые EACCES/ENOSPC/zero write/reader cleanup error, сохранение работающего runtime и следующая операция очереди. Дополнительно выполнены **64 HTTP + 64 TLS загрузки**, по восемь параллельно: 32 успешных, 96 ожидаемых ограниченных отказов; partial files после серий — ноль. TLS использует только собственный явно доверенный для одного Agent сертификат, без изменения системного trust store. В отдельном stalled-body тесте незавершённый socket закрывается самим отказом; ноль sockets в stress-сводках измерен после закрытия собственного лабораторного Agent/server.

В ходе проверки сохранён старый контракт AbortError общих fetch helpers; промежуточный тест обнаружил смену имени, она исправлена. Первое широкое испытание также требовало настройки task-owned trust fixture directory; этот setup-отказ не выдаётся за отказ приложения. История промежуточных запусков остаётся в собственном runtime этапа.

Пределы: дисковый ENOSPC внедрён на границе write, системный диск не заполнялся. Не доказаны поведение при физическом зависании файловой системы, сбое питания, Windows ACL/UAC переходе, полной native установке, внешнем GitHub outage и месяцы эксплуатации. Архивная распаковка и служебный lifecycle этим этапом не переписывались. Подготовленные исходники требуют общей сборки, native UI/installer приёмки и релизной проверки родительской задачи.
