## Что уже сделано хорошо и должно сохраниться

- Мини-щит в реальном снимке `installed-3.7.9-widget-hover.png` содержит чистый белый power-контур без чёрной галочки. Правило `shield-widget.css:218–225` должно сохраниться, включая немедленное `visibility:hidden` галочки при hover и обратимость после ухода указателя.
- Настоящая готовность компонентов уже используется через `rubyTelegramReady`, `rubyZapretReady`, `rubyDnsReady`. Сам статус Windows-службы недостаточен для «подключено»; эту границу не ослаблять при редизайне.
- У модального подтверждения есть именованный dialog, возврат фокуса, Tab trap и Escape (`renderer.js:11543–11577`); у мини-щита есть `aria-live` и предотвращение одновременных действий. Эти контракты необходимо перенести без регрессий.
- Система уже поддерживает reduced motion, узкие окна, скрытие анимации в невидимом мини-щите, локальные кириллические шрифты и собственные SVG. Новый дизайн должен опираться на эти возможности.
- Монохромная Lagom-идентичность различима. Навигация и кнопки имеют подписи, состояние не передаётся только цветом.

## Решение дизайна

Развивать нынешний спокойный чёрно-белый Lagom: отдельные уровни тёмных поверхностей, ясная иерархия действия и результата, более лёгкий рабочий шрифт, открытые объяснения, точные состояния. Не добавлять декоративные фоновые движения или имитацию графиков. Подробный контракт находится в [design-proposal.md](design-proposal.md). Изменения сетевых контрактов и сервисов рассматриваются отдельными аудитами.

## Коррекция после native-проверки масштаба

Головной исполнитель сообщил о фактическом clipping Telegram при zoom 200% / эффективном viewport 680px. Дочерний исполнитель не управлял этим native instance. Адресный анализ подтвердил причину: основной Telegram grid задавал `grid-template-columns`, `height` и `overflow` через `!important`, а media `max-width:860px` задавал обычные значения с такой же specificity. Это оставляло две колонки при сработавшем breakpoint. Аналогичная коллизия была у settings grid и общего screen overflow.

В `compact-surfaces.css:1224` снято `!important` с этих исходных Telegram layout-свойств и высот/overflow дочерних form/status; общий screen overflow теперь позволяет narrow media включить прокрутку. В `compact-surfaces.css:1475` исходный settings grid также использует обычные declarations. Поэтому существующее правило `max-width:860px` действительно выбирает одну колонку и auto document height. Settings screen разрешает вертикальную прокрутку также в широком низком окне: постоянные descriptions могут увеличить высоту документа. Telegram primary actions используют `repeat(2,minmax(0,1fr))`, допускают перенос длинного текста и при `max-width:600px` переходят в одну колонку. Широкое окно сохраняет два panel columns; новая цепочка глобальных `!important` не добавлена.

Индивидуальные descriptions в `renderer.js:11440–11463` ранее находились только в `sr-only` span и появлялись визуально через help hover/focus. Kp теперь выводит постоянный `.toggle-setting-description`; targeted CSS `compact-surfaces.css:1582` располагает текст во второй строке setting row, с переносом и без абсолютного overlay. `aria-describedby` switch ссылается на этот description. Причина disabled по-прежнему имеет приоритет над обычным описанием. Help focus/hover/click/Escape и его viewport positioning сохранены; `aria-controls` указывает на отдельный tooltip только когда он существует. Постоянный description не объявлен `role=tooltip`.

Проверки перед повторным native render: `production-ui-state.test.mjs` — 5 tests, включая component output contract для постоянного description, disabled reason, закрытого/открытого tooltip relationship и отсутствующего description; renderer syntax, parse обеих CSS и whitespace — PASS. Component contract использует изолированный hook/JSX harness, а не production render. Это не доказательство визуального отсутствия clipping: required follow-up у головного исполнителя — actual 680px/200% Telegram + settings, wide mode, достижимость нижних controls через scroll и прежний tooltip focus/hover. CI source этой правкой не изменён.

### Остаточный вертикальный конфликт, найденный повторным native render

Второй native прогон головного исполнителя подтвердил одну колонку, но обнаружил overlap: в [реальном снимке после первого исправления](native-ui/telegram-zoom200-after-columns.png) status panel закрывает второй ряд form actions. Дочерний исполнитель просмотрел этот сохранённый снимок; новых native действий не выполнял. Переданные головным исполнителем computed values при эффективном viewport 680px: layout `height=311.6px`, `min-height=100%`, `flex=0 1 auto`, auto grid tracks `148.805px 148.797px`; form `height=148.8px`, `min-height=0`. При этом actions занимают Y 218.1–312.1px, update card — 334.1–417.1px, выходя за нижний край form 266.2px. Advanced details сжался до 2px, log list — до 0px. Значит переход одной ширины был недостаточен: row sizing/flex shrink продолжал распределять ограниченную высоту вместо высоты содержимого.

Дополнительное narrow правило в `compact-surfaces.css` задаёт Telegram layout `flex:none`, `min-height:0`, `grid-auto-rows:max-content`; form/status имеют intrinsic `min-height:min-content`, а прямые дети form не сжимаются. В `final-polish.css` narrow log list получает `flex:none`, сохраняя ограниченную максимальную высоту и внутреннюю прокрутку. В обоих исходных log list правилах снята ненужная важность flex declaration, чтобы responsive override действительно сработал. Фиксированных пиксельных высот панелей не добавлено; широкий режим сохраняет прежнюю заполненную рабочую область.

Отдельный native `getByRole('tooltip')` timeout после первого исправления нельзя считать доказательством отказа hover: description перестал быть tooltip, а настоящая hover-копия тогда не имела tooltip role и была исключена из accessibility tree. Контракт исправлен: только реально открытый popup получает `role=tooltip` и уникальный ID; help при открытии ссылается на этот один popup через `aria-describedby`, при закрытии — на постоянный description. Switch всегда описывается постоянным текстом. Это устраняет неверную role у статического текста и делает реальный popup доступным для semantic lookup. События и позиционирование Kp не подменялись.

После этих дополнительных изменений: 5/5 focused Node tests, renderer syntax, обе CSS parse (0 warnings), `git diff --check` — PASS. Код передан на ещё один actual native rerender. Последний overlap снимок является доказательством дефекта до этой второй коррекции; успешное устранение overlap и настоящий hover/focus должны быть подтверждены головным исполнителем отдельным readback.

### Общий intrinsic flow после проверки пяти разделов
