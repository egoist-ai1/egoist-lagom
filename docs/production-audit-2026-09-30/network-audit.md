# Сеть и IPC: независимая повторная проверка

Дата: 30.09.2026 (Europe/Moscow). Исходная версия 3.7.9, коммит `d56eb9327fa75a88e91fae62b8d7ea3ed095dcf2`. Этот документ фиксирует исходные дефекты до исправлений. Итоги исправлений добавляются отдельно, чтобы не смешивать исходную проверку и результат.

Проверены Node-модули VPN, системного прокси, DNS/DoH, подписок, координации сетевых операций, их общие контракты и существующие тесты. Проверка не изменяет службы, настройки адаптеров и пользовательские подключения. Новые отказные случаи воспроизводятся на реальном HTTP-сервере `127.0.0.1` либо изолированных транспортных/IPC fixtures; это проверка настоящих функций исходников, а не испытание реального VPN-провайдера.

## Другие замечания и ограничения

| ID | Приоритет | Наблюдение и предлагаемый объём |
|---|---|---|
| N07 | Средний | `vpn:speedtest-cancel` меняет только флаг. Уже открытые TLS-сокеты и текущий параллельный download не получают отмену; они продолжают до конца фазы/таймера. Один download может ждать 25 секунд, а параллельные потоки расходуют трафик. Требуется передавать сигнал отмены в transport и destroy именно сокетов данного замера. Этот случай исходно установлен чтением кода, сетевой стресс-прогон production не проводился. |
| N08 | Средний | Объявленный общий бюджет подписки 45 секунд проверяется только перед очередным профилем. Одна попытка имеет три таймера по 10 секунд, задержки и дополнительный curl до 24–30 секунд: общий бюджет не является жёстким. Нужен общий AbortSignal/deadline, включая curl и backoff; не обрывать работающие подписки по произвольному более короткому бюджету. |
| N09 | Средний | Gravityless `queryServiceViaCim` возвращает `not-installed` при ошибке чтения SCM/CIM. Ошибка наблюдения должна давать `unknown`, чтобы координатор консервативно сохранял DNS-блокировки. `status()` не имеет защиты ревизии при invalidate и параллельном force — старый ответ может снова попасть в кеш после операции. |
| N10 | Низкий | `buildNetworkCombinatorInspection` по умолчанию сообщает `productVersion:'3.5.4'`; manager не передаёт текущую версию. Версию нужно получать из настоящего desktop/Core контекста, не заменять строку очередным постоянным номером. |
| N11 | Средний | `resolveHostDoh` удаляет таймер до `response.json()`; DNS fallback при ping может ждать незавершённое тело. Outer TCP timeout возвращает -1, но запрос остаётся живым. Нужен ограниченный JSON helper и очистка после завершения. |
| N12 | Средний | Запрошенный, но отсутствующий `requestedNodeId` молча заменяется первым узлом. Если узел был удалён во время UI-действия, пользователь подключается к другому серверу. Явный ID должен либо разрешиться точно, либо вернуть ошибку; авто-выбор допустим при отсутствии явного ID. |
| N13 | Средний | Ошибка `execFile(curl)` содержит исходную команду с полным URL. Локальное предупреждение fallback и возвращаемая транспортная ошибка могут раскрывать токен в пути подписки: общий log redactor не скрывает путь URL без query. Воспроизведено на искусственном URL `provider.invalid` через настоящие функции импорта, без чтения реальных подписок. |

Положительно проверены существующие границы: DNS-записи имеют транзакционный журнал и readback; восстановление учитывает GUID адаптера; системный прокси имеет снимок владения и проверку уведомления WinINet; импорт и refresh выполняют merge с актуальным состоянием и не возвращают удалённую подписку; HWID отключён до пользовательского согласия; network coordinator различает стабильное владение и активные операции; supervisor ограничивает повторения и имеет cooldown для временных сетевых ошибок. Эти меры уменьшают конкретные риски, но не доказывают непрерывную работу в течение месяцев.

Не проводились переключения живого VPN, публикация новых версий, изменения Windows DNS/SCM, реальный reboot, месячный soak, обход блокировки провайдера и нагрузка на чужие публичные сервисы. Данные fixture используют зарезервированные домены/IP и не содержат подписочных токенов.

## План исправлений и критерии приёмки

1. Ограничить route probe по времени и размеру полного ответа, принимать только корректный IP; неисправный endpoint должен освобождать ресурсы и давать неподтверждённый статус.
2. Завершать manual reconnect state при исключении и учитывать поколение операции, чтобы старый результат не отменял позднее ручное отключение.
3. Отменять задержку повтора немедленно; соблюдать allowlist HTTP retries, сохраняя стандартный повтор временных ошибок.
4. Сохранять точные server/SNI/URI; не изменять уже сохранённые адреса обратно предположениями о прошлой миграции.
5. Добавить fail-before/pass-after проверки для каждого исправленного нарушения, затем выполнить общий набор тестов проекта и build у координатора.

Санитизированное исходное доказательство: [network/baseline-repros.json](network/baseline-repros.json). Здесь нет обещания «идеально»: положительные результаты относятся к указанным сценариям и границам.

## Реализованные исправления

Все перечисленные сетевые дефекты N01–N13 исправлены в исходниках кандидата; это утверждение о проверенных программных границах, а не об уже установленной новой версии.

- N01–N02: route probe читает тело внутри контролируемой попытки, ограничивает ответ 64 КиБ и принимает только валидный IPv4/IPv6; `success:false` и неверный IP не подтверждают маршрут.
- N03: исключение ручного connect завершает состояние supervisor; результат предыдущего поколения не может снова включить восстановление после ручной отмены.
- N04–N05: отмена завершает backoff без ещё одного fetch; явный allowlist статусов соблюдается. Стандартная политика временных ошибок сохранена.
- N06: удалены все три места самовольной подмены домена: persisted state, Xray/sing-box config и ping. TLS SNI и URI сохраняются точно. Уже потерянный исходный адрес не угадывается и автоматически не меняется обратно; его можно восстановить из исходной подписки или конфигурации.
- N07: отдельный AbortSignal измерения проходит через CONNECT/TLS, latency/download/upload, параллельные потоки, задержки и последний TCP probe. Отмена закрывает только сокеты данного измерения, очищает таймеры и не останавливает независимый запрос. Завершение/ошибка/закрытие приложения отменяет оставшиеся операции измерения. Следующий замер получает новый контроллер. Ограничены чрезмерные HTTP-заголовки.
- N08: общий 45-секундный бюджет `auto` теперь действует во время тела ответа, retries, backoff и curl. Curl получает тот же сигнал отмены; после исчерпания бюджета не запускается новый fallback. Для фиксированного UA существующее время попыток сохранено. Внутренняя функция допускает меньший бюджет для вызывающего кода; значение выше 45 секунд не увеличивает установленный потолок.
- N09: ошибка SCM/CIM даёт `unknown`; PowerShell перестаёт превращать нетерминирующую ошибку CIM в отсутствие службы. Старое чтение не перезаписывает кеш после invalidate или более нового force-запроса.
- N10: версия inspection приходит из `app.getVersion()` через явный callback manager; вне настоящего контекста возвращается `unknown`, а не прежний номер 3.5.4. Связанный caller обновлён координатором.
- N11: DoH fallback ping читает ограниченное тело в пределах таймера, проверяет DNS Status и A-адрес; очистка TCP probe закрывает также fallback socket.
- N12: отсутствующий явный ID возвращает ошибку выбора сервера; неверный тип/пустой ID отвергается. Автовыбор по сохранённому/первому узлу остаётся только для вызова без явного ID.
- N13: URL в транспортных ошибках подписок редактируется локально перед предупреждением и возвратом ошибки; токен в pathname не попадает в сообщение.

Новый файл `tests/network-audit-2026-regression.test.mjs`: **22 проверки прошли**. Сначала 13 исходных проверок воспроизвели отказы на неизменённой 3.7.9; затем 5 дополнительных проверок воспроизвели N07/N08/N12 до их исправления; отдельная проверка воспроизвела N13 до исправления. Ещё 3 проверки уточняют lifecycle отмены, конкурирующий force-кеш и реальное выполнение PowerShell-контракта. Повтор по затронутому набору: **133 проверки, 133 pass, 0 fail, 0 skip**, около 6,22 секунды в данной среде.

Измерение отмены retry fixture: 1012 мс до исправления, 33–37 мс после, включая намеренную задержку 25–30 мс перед отменой; это не SLA публичной сети. Истёкший бюджет подписки проверялся реальным локальным HTTP stream с отдельным коротким бюджетом 40 мс; curl и TLS-сокеты проверены изолированными транспортными fixtures. PowerShell выполнялся настоящим Windows PowerShell с подменённой внутри процесса функцией CIM, не обращавшейся к живым службам. Повторный запуск speed test после отмены и сохранение независимого запроса подтверждены через настоящие зарегистрированные IPC handlers в fixture-контексте.

Часть существующего набора моделирует 90 дней таймеров и 143 009 неуспешных переподключений; это ускоренная модель scheduler, а не фактически прошедшие 90 дней. Все проверки выполнялись с временными каталогами в task work. Службы, DNS адаптеров, живые пользовательские процессы и GitHub-релизы этим аудитом не изменялись.

Финальный санитизированный протокол и хеши затронутых исходников: [network/validation.json](network/validation.json). Общую сборку, проверку настоящего интерфейса, Core и release-артефактов выполняет координатор после объединения изменений.

## Дополнительная проверка retention wrapper журналов

После исходного сетевого scope реализован отдельный guard в C# Core: три точных ProgramData `.wrapper.log`, порог 5 МиБ, один `.previous`, повтор через пять монотонных минут, отсрочка при native lock/ACL отказе и не более одного предупреждения в час. Работу DNS/служб ради ротации не прерывает. **10 изолированных групп PASS**, включая 144 реальные ротации, NTFS ACL/junction/sharing fixtures и helper настоящего compiled Core; Core Release build прошёл. Мягкий размерный предел, ограничения и команды подробно зафиксированы в [network/wrapper-log-maintenance.md](network/wrapper-log-maintenance.md), evidence — [network/wrapper-log-validation.json](network/wrapper-log-validation.json). Это устранение retention gap, а не обновление log4net или доказательство многомесячного uptime.
