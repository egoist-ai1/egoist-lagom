Audit baseline: published `3.7.9`, commit `d56eb9327fa75a88e91fae62b8d7ea3ed095dcf2`. Initial observations below are recorded before source changes; fix verification is appended separately.

## Checks and current runtime evidence

- Parent's configured baseline: generated build passed; Node suite `546 total / 545 passed / 0 failed / 1 skipped`. Skipped runtime behavior requires `LAGOM_XRAY_TEST_BINARY` and `LAGOM_DNS_TEST_WORK`; a skipped test is not coverage.
- Component-input reproduction uses real copies of the three immutable pinned archives in task scratch. SHA-256 pins were accepted while separately extracted executable bytes were changed. The reproduction receipt is saved under `release/initial-gap-reproductions.json`.
- Updater response-lifetime reproduction uses the unchanged production source inside an isolated VM and controlled response objects. It proves missing cleanup calls on those paths; it is not a production network outage or installed-client update.
- The full Node suite requires `EGOIST_PACKAGING_TEST_DIR` (absolute fixture root), `EGOIST_RELEASE_TEST_DIR`, `EGOIST_RELEASE_PYTHON`, `SHIELD_PYTHON`, `SHIELD_MAKENSIS` and task-local `TEMP`/`TMP`. Installer plan tests additionally need a matching `dist/package-integrity.json` and versioned EXE. Fixtures must remain outside product directories.
- [Electron 44.4.5](https://github.com/electron/electron/releases/tag/v44.4.5) is an official stable release published 2026-09-23; its pin records archive SHA-256 and an independent SHASUMS digest. [Electron's support policy](https://www.electronjs.org/docs/latest/tutorial/electron-timelines) covers the latest three stable major lines and the latest minor in each. This does not certify the whole recovered renderer dependency graph.
- `EgoistShield.Service.csproj` targets .NET `10.0.12`. [Microsoft's current support table](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) lists that patch and .NET 10 LTS through 2028-11-14. The Core is self-contained: it needs a new product build for runtime patches; installing a machine-wide .NET patch does not update the embedded runtime.
- The current npm lock is exact; native/recovered code is only partially covered by the SBOM. `prepare-release-assets.mjs` states that limitation. A zero npm advisory count does not cover native components or prove absence of vulnerabilities.
- `LICENSE.txt` expressly preserves third-party license terms, but broad product restrictions do not establish fulfillment of [sing-box's GPL terms](https://github.com/SagerNet/sing-box/blob/v1.14.0/LICENSE). The finding concerns missing distribution evidence, not a legal determination about process aggregation.

## Verified existing protections worth preserving

Canonical updater URLs, signed manifest schema, Ed25519 trust verification, signed size plus SHA-256/SHA-512, same-candidate recheck after download, anti-rollback state, bounded retries, checked Content-Range, read/idle deadlines, exact owned installer paths, protected staged ACL, process creation-time checks in the watchdog, preserved service/DNS readback and explicit recovery warnings are already present. These should remain covered by tests.

Neither this audit nor a successful short test establishes month-long stability, reboot recovery on all supported Windows versions, SmartScreen publisher trust, actual old-client automatic installation, or legal completeness of all bundled native components. The published `3.7.9` remains immutable while changes are prepared for a new candidate.

## Additional native-runtime finding

The old 18,243,033-byte WinSW 2.12.0 x64 wrapper (`05b82d46ad331cc16bdc00de5c6332c1ef818df8ceefcd49c726553209b3a0da`) embeds .NET 6. An isolated bundle inspection found actual CoreLib 6.0.13; [Microsoft's support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) ended .NET 6 support on 2024-11-12. Updating the application's .NET 10 Core does not patch that separate wrapper.

The candidate uses the same official WinSW 2.12.0 API/schema, `WinSW.NET461.exe`, running on installed Windows .NET Framework 4.8+. Its SHA-256 is `b5066b7bbdfba1293e5d15cda3caaea88fbeab35bd5b38c41c913d492aadfc4f`, size 655,872 bytes. The old [official asset](https://github.com/winsw/winsw/releases/download/v2.12.0/WinSW.NET461.exe) has a null GitHub digest; the pin is measured from that exact HTTPS vendor asset, rather than misrepresented as an independently signed checksum. Packaging re-authenticates it each time and includes the canonical wrapper in the zapret component inventory. Installer preflight/migration and read-only CLI compatibility checks are owned by the parent/service audit.

This is a narrow runtime improvement, not a claim that all WinSW dependencies are supported. Exact [WinSW source](https://github.com/winsw/winsw/blob/v2.12.0/src/WinSW.Core/WinSW.Core.csproj) merges log4net 2.0.12 and YamlDotNet 8.1.2 into that variant. [Apache's lifecycle table](https://logging.apache.org/log4net/download.html) lists log4net 2.x as end-of-life since 2024-09-12. Their full license/NOTICE files are supplied; a maintained wrapper or separately tested dependency rebuild is still a follow-up risk. No remote exploit is inferred merely from this version fact.

## Native source and license distribution evidence

The exact supplied WinDivert DLL and driver both match the [official v2.2.2 archive](https://github.com/basil00/WinDivert/releases/download/v2.2.2/WinDivert-2.2.2-A.zip) byte for byte. Its upstream license offers a choice of LGPLv3 or GPLv2; the previous notices' mandatory library/driver split was corrected. Binary correspondence receipt: `release/windivert-binary-correspondence.json`.

`resources/licenses/source-inputs.json` records every exact primary source route and module checksum. `sources.json` records 17 principal native texts, 158 module notices and 96 preserved primary upstream notices. Names and hashes identify supplied texts without asserting that every upstream test notice governs every compiled artifact. `SOURCE-DIRECTIONS.txt` identifies source/build correspondence and explicit limitations.

The source companion includes the exact sing-box VCS revision `0b8995879f29a9b98ee027bc17b75e101445b238`, Go 1.26.7 build metadata, all 135 dependency modules, and Cronet native library commit `f80ef37265e5ae43b62021553a3bfc763414656d`. The official library commit names native builder `d9872d6dd0d39cc7e042d1199d736f16fc40cf8c`, whose gitlink pins naiveproxy `c823360c60cf54aab2ee2ac1644f69cc611d94d5`; both source archives are included. This establishes a source direction, while actual native rebuild and external compiler/build inputs remain unverified.

`prepare-native-sources.py` performs bounded downloads (128 MiB per archive; 512 MiB total), validates source/module inputs, retains original source ZIPs without executing them, and writes fixed-timestamp companion entries. Repeating the complete offline companion generation produced identical bytes and SHA-256. Its final receipt is `release/native-source-companion.json`. Parent will generate the final package's own receipt after source freeze.

No clean installation, service mutation, reboot, key generation/signing, Git mutation or publication is performed by this release audit. Reports distinguish verified candidate behavior from the parent-owned final artifact and installed-system acceptance.
